# Module 2.1 Script With Fake Jira

## Frame The Leadership Problem And Define "Group DNA"

Duration: 40-50 minutes

Objective: Run Module 2.1 with explicit operational follow-through by using fake Jira to capture dependencies, open questions, owners, and next actions alongside the portfolio pack.

Use this version when you want the session to produce both:
- leadership content for the portfolio pack
- operational tasks for follow-up in fake Jira

Expected tools:
- Portfolio Pack captures for `Executive Update`, `Final Plan`, and `Internal Comms`
- Fake Jira actions for task lookup, task creation, comment capture, and status updates

## Moderator Opening

Use this opening:

> Today we are framing the leadership problem and defining Gucci Group's leadership DNA. In this version of the session, we will not only align on the content. We will also capture concrete follow-up actions in Jira so the work can move immediately after the workshop.

> As we go, we will save the working content into the portfolio pack and log operational actions into Jira. Portfolio captures hold the narrative. Jira holds the execution follow-through.

## Working Rule

Use this rule throughout the module:

- `Executive Update` captures why leadership should care and what decisions are needed
- `Final Plan` captures the current best working draft and is updated as the session progresses
- `Internal Comms` captures the stakeholder-facing summary
- fake Jira captures open tasks, follow-ups, unresolved choices, and owners

## Step 0. Pull Current Jira Context

Time: 3-5 minutes

Moderator prompt:

> Before we frame the leadership model, let's check whether there are already operational items in Jira that should shape this discussion.

Jira interaction:

Use prompts like:

> Show Jira tasks related to leadership, talent, rollout, or training.

> Summarize current Jira status for manager enablement, leadership update drafting, and rollout readiness.

Working assumption:
- existing tasks may already reflect rollout constraints, enablement needs, or leadership communication dependencies

Expected output:
- quick view of relevant current tasks
- awareness of live dependencies that should shape the discussion

Capture:
- none yet, unless current Jira context materially changes the framing

## Step 1. Define The Leadership Problem

Time: 8-10 minutes

Moderator prompt:

> What is the leadership problem we are actually trying to solve at Group level?

Follow-up prompts:
- Where does brand autonomy need to remain protected?
- Where does the Group need more consistency?
- If nothing changes, what business or talent risks remain?
- Which of those risks already appear in operational work or rollout dependencies?

Portfolio capture:

> Update the Executive Update with the business problem, the autonomy versus Group consistency tension, and why this matters now.

Jira interaction:

If a concrete risk or dependency is identified, capture it immediately:

> Create a Jira task for the main unresolved leadership design risk from Step 1.

Suggested task shape:
- Title: `Define Group vs brand leadership boundaries`
- Description: `Clarify which leadership expectations must be consistent at Group level and which should remain brand-specific.`
- Status: `todo`

Expected output:
- draft problem statement
- first operational risk ticket, if needed

## Step 2. Surface The CEO Lens

Time: 7-8 minutes

Moderator prompt:

> If we were speaking with the CEO, what would we want to understand about the business direction and the leadership culture needed to support it?

Follow-up prompts:
- What does success look like for the Group in the next 3 to 5 years?
- What leadership behaviors are non-negotiable across the Group?
- What must stay distinct by brand?
- Which decisions need direct executive sponsorship?

Portfolio capture:

> Update the Final Plan with the CEO lens, business ambition, and the design criteria for shared versus brand-specific expectations.

> Refresh the Executive Update with any new leadership asks or sponsorship needs.

Jira interaction:

Use Jira comments to preserve executive direction against the relevant task:

> Add a comment to the leadership boundaries task saying the CEO lens requires shared expectations for mobility and talent consistency, while preserving brand-specific leadership expression.

If no task exists yet:

> Create a Jira task for executive sponsorship decisions needed for the leadership model.

Suggested task shape:
- Title: `Confirm executive sponsorship for Group DNA model`
- Description: `Confirm the leadership decisions and sponsorship required to move the first-pass model into design and review.`

Expected output:
- CEO-informed design criteria
- explicit sponsorship task or comment trail

## Step 3. Surface The CHRO Lens

Time: 7-8 minutes

Moderator prompt:

> From the CHRO perspective, what is Group HR trying to enable through this model?

Follow-up prompts:
- How should the model support recruitment, appraisal, development, succession, and mobility?
- What should Vision, Entrepreneurship, Passion, and Trust mean in observable behavior terms?
- What needs to vary by leadership level?
- Which design tasks should HR own after this session?

Portfolio capture:

> Update the Final Plan with the HR intent, first interpretation of the four themes, and the first view of level differentiation.

Jira interaction:

Create implementation tasks for HR-owned design work:

> Create a Jira task for drafting behavior indicators by level for Vision, Entrepreneurship, Passion, and Trust.

Suggested task shape:
- Title: `Draft behavior indicators for Group DNA model`
- Description: `Translate the four headline themes into level-based behavioral indicators for use in the competency matrix.`

Optional follow-up:

> Add a comment to that task saying the output must support recruitment, appraisal, development, succession, and mobility.

Expected output:
- HR design intent in the Final Plan
- follow-up Jira task for detailed model design

## Step 4. Build The First-Pass Competency Model

Time: 10-12 minutes

Moderator prompt:

> Let's define the first-pass competency model using Vision, Entrepreneurship, Passion, and Trust.

Follow-up prompts:
- For each theme, what are 2 to 3 critical behaviors?
- How should those behaviors differ across three leadership levels?
- Which behaviors are essential and observable?
- Which areas are still unresolved enough to need follow-up tasks?

Portfolio capture:

> Update the Final Plan with the current best draft of the competency model. Treat this as a full replacement of the prior Final Plan content, not an append.

Jira interaction:

For each unresolved area, create or update a task.

Use prompts like:

> Create a Jira task for validating level architecture for the competency matrix.

> Create a Jira task for testing whether the behavior model works across multiple brands.

> Add a comment to task #<id> saying Trust behaviors need examples for cross-brand collaboration and credibility.

Suggested task shapes:
- `Validate level architecture for competency matrix`
- `Test Group DNA model against brand-specific leadership scenarios`

Expected output:
- stronger first-pass model
- clear list of remaining design tasks in Jira

## Step 5. Map Use Cases

Time: 5-7 minutes

Moderator prompt:

> Where will this model create value first, and how should it be used in practice?

Follow-up prompts:
- How should it inform recruitment?
- How should it support appraisal?
- How should it shape development and succession?
- How should it support mobility across brands, functions, or markets?
- Which use case should be piloted first?

Portfolio capture:

> Update the Final Plan with the prioritized use cases and sequencing assumptions.

> Save Internal Comms with the stakeholder-facing summary of what the model is for and what teams should expect next.

Jira interaction:

Convert use cases into pilot or delivery tasks:

> Create a Jira task for piloting the Group DNA model in recruitment.

> Create a Jira task for integrating the Group DNA model into appraisal guidance.

> Create a Jira task for defining mobility decision criteria using the model.

Suggested task shapes:
- `Pilot Group DNA model in recruitment`
- `Integrate Group DNA into appraisal guidance`
- `Define mobility criteria using Group DNA`

Expected output:
- use case prioritization in the portfolio pack
- delivery backlog in Jira

## Step 6. Close And Confirm Outputs

Time: 5 minutes

Moderator closing:

> Before we close, let's confirm what we are taking forward: the problem statement, the first-pass Group DNA, the model structure, the priority use cases, and the follow-up work now captured in Jira.

> We should leave this session with both a leadership narrative and an execution trail.

Portfolio capture:

> Refresh the Executive Update with what was agreed, what still needs endorsement, and what the next deliverables are.

> Finalize Internal Comms with what the workshop covered, what was aligned, and what happens next.

Jira interaction:

Use the end of the session to set visible next-step status:

> Show all Jira tasks created for Module 2.1.

> Update the task status for the highest-priority follow-up to `in_progress`.

> Add a comment to the highest-priority task saying Module 2.1 is complete and follow-up design work is now underway.

Expected output:
- final executive summary
- internal stakeholder summary
- visible Jira-backed execution plan

## Portfolio And Jira Interaction Guide

Use these interaction cues during the session:

When the leadership problem is agreed:

> Save this as Executive Update.

When the working model evolves:

> Update the Final Plan with the latest consolidated draft.

When stakeholder messaging is ready:

> Save this as Internal Comms.

When a risk, owner, dependency, or unresolved design choice appears:

> Create a Jira task for that follow-up.

When a live task needs more context:

> Add a Jira comment with the decision or design note from the workshop.

When a follow-up becomes active:

> Update the Jira status to in progress.

## Simple Capture Rule

- Step 0: inspect Jira context
- Step 1: update `Executive Update`, create first risk task if needed
- Step 2: update `Final Plan` and `Executive Update`, add Jira sponsorship comments or tasks
- Step 3: update `Final Plan`, create HR design task
- Step 4: update `Final Plan`, create validation and refinement tasks
- Step 5: update `Final Plan`, save `Internal Comms`, create pilot and implementation tasks
- Step 6: refresh `Executive Update` and `Internal Comms`, review Jira backlog and set next task to `in_progress`
